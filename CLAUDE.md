# slug-pages

## Repository

Anonymous, no-login scratchpad — navigate to any URL and start typing. Markdown live-preview editor, running 100% on Cloudflare edge (Workers + D1).

Read `README.md` before making changes — it documents the project pitch and the domain's business rules. Read `CONTEXT.md` for the domain vocabulary. Significant, hard-to-reverse decisions are recorded in `docs/adr/` — check it before revisiting one, and add an entry when making a new one (see the `domain-modeling` skill for the format).

## Stack

- TanStack Start (SSR, React 19) on Cloudflare Workers — server functions are the entire backend, no separate API.
- Vite 8, `@cloudflare/vite-plugin`, `wrangler`.
- Biome for lint/format (no ESLint, no Prettier).
- pnpm.
- Data layer: Cloudflare D1 + Drizzle ORM. Schema and client are wired up (see Source); no server function reads/writes it yet.
- Vertical Slice / feature-folder organization for server-side logic — TODO, only the default file-router scaffold exists so far.
- Live-preview Markdown editing mechanism — TODO, not decided (CodeMirror 6 + decoration plugin is the current lean, not finalized).

## Skill Loading

Before editing files for a substantial task:

- Run `pnpm dlx @tanstack/intent@latest list` from the repo root to see available local skills.
- If a listed skill matches the task, run `pnpm dlx @tanstack/intent@latest load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

Enabled skill scope is `@tanstack/*` only (see `intent.skills` in `package.json`).

## Source

The default TanStack Start file-router scaffold, plus the data layer:

- `src/router.tsx` — router instance (`createRouter`), preload/caching config.
- `src/routes/__root.tsx` — root route, renders the full HTML document (`<html>`, `<head>`, `<Scripts />`).
- `src/routes/index.tsx` — home route.
- `src/routeTree.gen.ts` — auto-generated by the TanStack Router CLI (`pnpm generate-routes`). Do not hand-edit.
- `src/styles.css` — global styles.
- `src/db/schema.ts` — Drizzle schema (`pages` table: `slug` PK, `content`, `updatedAt`).
- `src/db/client.ts` — Drizzle D1 client (`db`), reads the `DB` binding via `cloudflare:workers`.
- `drizzle.config.ts` / `drizzle/` — migration config and generated SQL migrations.
- `wrangler.jsonc` — `d1_databases` binding (`DB` → `slug-pages-db`), `migrations_dir: "drizzle"`.
- `worker-configuration.d.ts` — generated `Env` type (`wrangler types`). Do not hand-edit.

No server function reads or writes `pages` yet — this section should be expanded once one lands.

## Validation

- `pnpm check` — Biome: format + lint + organize imports.
- `pnpm typecheck` — `tsc --noEmit`.
- `pnpm build` — Vite build.
- `pnpm test` — Vitest (`vitest run`, `passWithNoTests: true` — no tests exist yet, add real ones alongside real logic, e.g. server functions). Exported functions with real logic should have a matching `*.test.ts`.
- CI (`.github/workflows/ci.yml`) runs `check`, `typecheck`, `build`, and `test` on every push/PR to `main`. CD (`.github/workflows/cd.yml`) runs `pnpm run db:migrate:remote` then `pnpm run deploy` on push to `main`, using the `prod` GitHub Environment (`CLOUDFLARE_API_TOKEN` as environment secret, `CLOUDFLARE_ACCOUNT_ID` as environment variable).
